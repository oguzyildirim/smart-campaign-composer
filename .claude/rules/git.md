# Git Workflow Rules

- Inspect git status before modifying files.
- Never overwrite unrelated user changes.
- Keep each milestone in a separate, reviewable commit.
- Do not commit automatically.
- Do not push to remote repositories without explicit permission.
- Do not rewrite shared Git history.
- Never use git reset --hard, git clean -fd, or destructive checkout
  commands to resolve a problem without explicit authorization.
- Before suggesting a commit, run relevant tests and inspect the diff.
- Use clear commit messages describing the change.
- Do not include .env, credentials, real user data, or temporary artifacts.
- Keep ai-sessions exports separate from application source changes.
