## 1. Analysis

### 1.1 Things worth flagging

- **M2 vs M3 ordering.** M2's deliverable says "a brief produces a validated segment",
  but Claude arrives in M3. M2 therefore covers *segment-rule JSON → validation →
  parameterized SQL → recipient count*, using a hand-written rule in place of the LLM.
  M3 adds the brief → rule step in front of it.
- **Global rate limit (100 msg/s per channel, across all workers)** needs shared state.
  Kafka and Postgres are already in the stack; Redis would be a new dependency.
  Recommendation: Postgres-backed token bucket per channel (tokens acquired in batches),
  and retries go through the same limiter. Confirmed when drafting M5.
- **SMS 160 characters and Turkish letters.** ş/ğ/ı force UCS-2 encoding (70-char
  segments) on real networks. The spec says 160 characters → count runes and document
  the GSM-7 caveat.
- **Personalization can break limits.** `{{first_name}}` length varies, so validate the
  worst case at approval (longest value in the audience) *and* re-validate per recipient
  right before sending.
- `CLAUDE.md` imports `@project.md`, which is gitignored, so anyone cloning the repo
  won't have it.

import "time"

// RetryPolicy schedules retries of transient failures: exponential
// backoff with full jitter, where a provider's Retry-After is a lower
// bound. Every delay is capped at MaxDelay. The number of attempts is
// stored per delivery (max_attempts), not here.
type RetryPolicy struct {
	BaseDelay time.Duration
	Factor    int
	MaxDelay  time.Duration
}

// Ceiling is the backoff ceiling after the given attempt (1-based):
// BaseDelay·Factor^(attempt-1), capped at MaxDelay.
func (p RetryPolicy) Ceiling(attempt int) time.Duration {
	d := p.BaseDelay
	for i := 1; i < attempt && d < p.MaxDelay; i++ {
		d *= time.Duration(max(p.Factor, 1))
	}
	return min(d, p.MaxDelay)
}

// Backoff is the full-jitter delay after attempt: rnd (in [0, 1)) times
// the ceiling. Full jitter spreads retries of many deliveries that failed
// together, so they do not return to the provider in lockstep.
func (p RetryPolicy) Backoff(attempt int, rnd float64) time.Duration {
	return time.Duration(rnd * float64(p.Ceiling(attempt)))
}

// Delay is the wait before the next attempt: the backoff, or the
// provider's Retry-After when that is longer, capped at MaxDelay.
func (p RetryPolicy) Delay(attempt int, retryAfter time.Duration, rnd float64) time.Duration {
	return min(max(p.Backoff(attempt, rnd), retryAfter), p.MaxDelay)
}

// Run polls and handles batches until ctx ends. On shutdown it stops
// polling, gives in-flight messages Grace to finish, and commits only if
// the whole batch finished.
func (c *Consumer) Run(ctx context.Context) error {
	for {
		fetches := c.client.PollRecords(ctx, c.cfg.MaxPollRecords)
		if fetches.IsClientClosed() || ctx.Err() != nil {
			c.client.AllowRebalance()
			return nil
		}
		fetchFailed := false
		fetches.EachError(func(topic string, partition int32, err error) {
			fetchFailed = true
			c.logger.WarnContext(ctx, "kafka fetch error", "topic", topic, "partition", partition, "error", err)
		})
		recs := fetches.Records()
		if len(recs) == 0 {
			c.client.AllowRebalance()
			if fetchFailed && !sleepCtx(ctx, fetchErrorPause) {
				return nil
			}
			continue
		}

		finished := c.handleBatch(ctx, recs)
		if finished {
			cctx, cancel := context.WithTimeout(context.WithoutCancel(ctx), commitTimeout)
			if err := c.client.CommitRecords(cctx, recs...); err != nil {
				// The batch is redelivered; claims make that harmless.
				c.logger.WarnContext(ctx, "kafka commit failed", "records", len(recs), "error", err)
			}
			cancel()
		}
		c.client.AllowRebalance()
		if !finished {
			c.logger.InfoContext(ctx, "shutdown left messages unfinished; they will be redelivered")
			return nil
		}
	}
}

// handleBatch handles every record concurrently and reports whether all of
// them finished. Work continues for Grace after ctx ends.
func (c *Consumer) handleBatch(ctx context.Context, recs []*kgo.Record) bool {
	work, cancelWork := context.WithCancel(context.WithoutCancel(ctx))
	defer cancelWork()
	stop := context.AfterFunc(ctx, func() {
		timer := time.AfterFunc(c.cfg.Grace, cancelWork)
		context.AfterFunc(work, func() { timer.Stop() })
	})
	defer stop()

	var g errgroup.Group
	g.SetLimit(max(c.cfg.Concurrency, 1))
	for _, rec := range recs {
		g.Go(func() error { return c.handle(work, rec) })
	}
	return g.Wait() == nil
}

// handle retries the handler with capped backoff until it succeeds or
// work ends, which is returned as an error.
func (c *Consumer) handle(work context.Context, rec *kgo.Record) error {
	backoff := handlerRetryMin
	for {
		err := c.handler(work, rec.Value)
		if err == nil {
			return nil
		}
		if work.Err() != nil {
			return work.Err()
		}
		c.logger.WarnContext(work, "message handler failed; retrying",
			"topic", rec.Topic, "partition", rec.Partition, "offset", rec.Offset, "error", err, "retry_in", backoff.String())
		if !sleepCtx(work, backoff) {
			return work.Err()
		}
		backoff = min(backoff*2, handlerRetryMax)
	}
}

func Compile(rule Rule, now time.Time) (Predicate, error) {
	if len(rule.Conditions) == 0 {
		return Predicate{}, fmt.Errorf("compile segment: rule has no conditions")
	}
	b := &builder{}
	clauses := make([]string, 0, len(rule.Conditions))
	for _, c := range rule.Conditions {
		clause, err := b.condition(c, now)
		if err != nil {
			return Predicate{}, fmt.Errorf("compile segment: %w", err)
		}
		clauses = append(clauses, "("+clause+")")
	}
	return Predicate{SQL: strings.Join(clauses, " AND "), Args: b.args}, nil

## Milestone 7 — Hardening and submission

### D53. Failure scenarios as integration tests with test-side faults

The scenario suite (`internal/delivery/scenario_integration_test.go`)
drives the real claim, limiter, Postgres store, and provider client
against an in-process mock provider, with Kafka only where the queue
itself is under test (replay, shutdown and restart). Faults that the mock
provider cannot produce are injected from the test through the existing
ports:
- a `delivery.Store` wrapper whose `Record` "crashes" after the provider
  accepted the message;
- a `delivery.Provider` wrapper that holds a response until the worker's
  lease has expired;
- an HTTP middleware in front of the provider that logs every request's
  key, arrival time, status, and `Retry-After`.

Retry spacing becomes checkable by fixing the processor's jitter source
(`ProcessorConfig.Rand`). Each retry must then arrive no earlier than
`policy.Delay(attempt, Retry-After, 0.5)` after the previous request.

*Alternative:* fault-injection hooks in production code (e.g. a "crash
after send" flag in the worker). Rejected: the ports already allow it, and
production code stays free of test switches.
*Alternative:* scenario tests against the Compose stack. Rejected for the
reasons in D13; the stack is exercised by `make smoke` instead.

The rate-limit scenario lowers the limit to 20 + 5 per second so a few
hundred deliveries saturate it within seconds. The 95/s production value
is checked by the smoke run against the provider's own sliding-window
counter.

### D54. Smoke test as a Go program

`make smoke` runs `cmd/smoke` against the running stack. It is not built
into any image.
*Alternative:* a shell script with `curl` and `jq`. Rejected: it would add
`jq` as a host requirement, SSE parsing in shell is fragile, and the Go
version decodes the API's own response types (`httpapi`, `mockprovider`),
so it breaks at compile time if they drift.

The provider's statistics are cumulative since it started, so the smoke
test compares differences before and after its campaign. It tolerates one
documented case: a send accepted on the last attempt whose response was
lost is delivered but recorded as `retries_exhausted`. Any other mismatch
fails the run.

### D55. Fuzzing and vulnerability checks

Go native fuzz targets cover the parsers that take untrusted input:
- the segment rule validator and compiler;
- the template parser and per-recipient renderer;
- the LLM output decoders.

target for a while. The properties are invariants rather than exact

placeholder syntax.

sides of a placeholder can join into one rune, but stored content and
values are always valid UTF-8 (JSON decoding, Postgres `text`).

## What the gap analysis found and what I added

Existing coverage was already strong. The gaps were the specific failure scenarios, API validation on every endpoint, fuzz tests, an endpoint-level injection test, govulncheck, and the smoke test.

- **Failure-scenario tests** (`internal/delivery/scenario_integration_test.go`), 9 tests including 5 provider-failure subtests:
  - 5xx bursts, 429 storms with Retry-After, timeouts, "accepted but response lost", and permanent 4xx. Retry spacing is checked against backoff and Retry-After for every key.
  - Consent at approval, consent revoked before sending, and recipients with consent on only one channel.
  - Four workers sharing the rate limiter: every 1-second window stays at or below 25 requests (20/s plus burst 5), and the test also checks the limiter was actually saturated.
  - A worker crash after the provider accepted, and a lease that expires while the first worker is still sending.
  - Shutting all workers down mid-campaign and restarting them.
  - Faults are injected through test-side wrappers, so no production code changed.
- **API validation** (`internal/httpapi/validation_test.go`): 30 bad-request cases across all campaign endpoints, plus a 500 test that checks error bodies contain no SQL, driver errors or stack traces.
- **AI safety through the endpoints:** the prompt-injection corpus, plus 8 hostile model outputs (approve flags, raw SQL, `{{phone}}`, HTML, overlong SMS). Nothing gets approved, queued or stored.
- **Fuzzing:** 5 targets (segment rules, templates, rendering, both LLM output decoders). Their seed corpora run in `make test`, and a new `make fuzz` runs them for real.
- **New commands:** `make vuln` runs govulncheck v1.9.0, and `make smoke` runs a new Go program in `cmd/smoke`.
- **Docs:** README (status, testing, smoke, a requirements-to-tests coverage table, "Not done" list), a new Milestone 7 section in DECISIONS.md (D53–D55), and CLAUDE.md commands and layout. `.env.example` needed no change.
