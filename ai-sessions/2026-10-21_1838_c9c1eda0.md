## 🔴 Critical: things that aren't working

**1. `claude.md` is never loaded.** Claude Code only looks for `CLAUDE.md` (uppercase), and Linux treats `claude.md` as a different file. When this session started, only `.claude/rules/git.md` was loaded, not your project instructions. Fix: `mv claude.md CLAUDE.md`.

**2. The protection hook blocks nothing, because `jq` isn't installed.** I fed it a Write to `.env` and a `git push -f`. Both returned exit 0 with `jq: command not found`. The script reads the tool input with `jq`, so every field comes back empty and every call is allowed. Fixes:
- `sudo apt install jq`
- Make the hook fail closed: at the top, `command -v jq >/dev/null || { echo "jq missing; hook cannot verify" >&2; exit 2; }`

**3. `golang-always.mdc` is never loaded.** `.mdc` and the `alwaysApply`/`globs` keys are Cursor's format. Claude Code only reads `.md` rules with a `paths:` key. It also points to about 20 skills you don't have, including `golang-safety`, `golang-security`, `golang-performance`, `golang-grpc`, the cobra/viper skills and the samber-* skills. The `golang-how-to` skill already does this routing. I'd delete it. Or replace it with a 5-line `.md` rule (`paths: ["**/*.go"]`) that names the few skills that matter here.

**4. Nothing stops Claude from reading `.env`.** The hook only checks Write/Edit and some `cat`/`head`/etc. commands. The **Read** tool isn't covered at all, and neither are `grep KEY .env`, `printenv` or `docker compose config` (which prints the secrets it fills in). Hooks that block bad patterns are easy to get around, so use permission deny rules. They're the reliable way to do this:
```json
"permissions": {
  "deny": ["Read(./.env)", "Read(./.env.*)", "Bash(git push --force:*)", "Bash(git push -f:*)", "Bash(git reset --hard:*)", "Bash(git clean:*)"],
  "allow": ["Read(./.env.example)"]
}
```
Keep the hook as a second layer.
