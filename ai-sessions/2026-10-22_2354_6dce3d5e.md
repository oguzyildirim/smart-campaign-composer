- **Global rate limit (100 msg/s per channel, across all workers)** needs shared state.
  Kafka and Postgres are already in the stack; Redis would be a new dependency.
  Recommendation: Postgres-backed token bucket per channel (tokens acquired in batches),

  the GSM-7 caveat.

const (
	maxConns          = 10
	maxConnIdleTime   = 5 * time.Minute
	healthCheckPeriod = 30 * time.Second
)

// errInvalidURL is returned instead of the pgx parse error, which can quote
// the connection string including its password.
var errInvalidURL = errors.New("invalid database URL")

// NewPool parses databaseURL and returns a pool. Connections are opened
// lazily, so a pool is returned even while the database is down; readiness
// checks surface that state instead of crashing the process.
func NewPool(ctx context.Context, databaseURL string) (*pgxpool.Pool, error) {
	cfg, err := pgxpool.ParseConfig(databaseURL)
	if err != nil {
		return nil, errInvalidURL
	}
	cfg.MaxConns = maxConns
	cfg.MaxConnIdleTime = maxConnIdleTime
	cfg.HealthCheckPeriod = healthCheckPeriod

	pool, err := pgxpool.NewWithConfig(ctx, cfg)
	if err != nil {
		return nil, fmt.Errorf("create postgres pool: %w", err)
	}
	return pool, nil
}

// Checker reports whether the database accepts connections.
type Checker struct {
	pool *pgxpool.Pool
}

// NewChecker returns a health checker backed by pool.
func NewChecker(pool *pgxpool.Pool) Checker { return Checker{pool: pool} }

// Check pings the database.
func (c Checker) Check(ctx context.Context) error {
	if err := c.pool.Ping(ctx); err != nil {
		return fmt.Errorf("ping postgres: %w", err)
	}
	return nil
}

## Segment preview

A segment rule is a small JSON document. Conditions are ANDed; each field
may appear once.

| Field                       | Ops          | Value                                         |
| --------------------------- | ------------ | --------------------------------------------- |
| `city`                      | `eq`, `in`   | string / array of ≤ 20 strings, 1–64 letters; case- and Turkish-letter-insensitive (`Istanbul` = `İSTANBUL`) |
| `locale`                    | `eq`, `in`   | `tr`, `en`                                    |
| `added_to_cart_within_days` | `eq`         | integer 1–365: ≥ 1 cart event in the window   |
| `no_purchase_within_days`   | `eq`         | integer 1–365: no order in the window         |
| `purchased_within_days`     | `eq`         | integer 1–365: ≥ 1 order in the window        |
| `order_count`               | `gte`, `lte` | integer 0–10000 (all-time orders)             |

"Within N days" means the last `N × 24h` up to the request time.

That's expected with the current setup, not a bug. Postgres has no host port published. Milestone 1 made that choice on purpose (DECISIONS.md D11): only the API, mock provider and frontend are exposed on `127.0.0.1`, and Postgres and Kafka are reachable only inside the Compose network. So nothing is listening on `localhost:5432` for your client to connect to.

You have two options.

**1. Connect through the container (no changes needed):**
```bash
docker compose exec postgres sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB"'
```
This uses the credentials from your `.env` inside the container, so you never have to type them.

**2. Publish the port locally for a GUI client (DBeaver, GoLand, etc.):** create `docker-compose.override.yml` in the repo root. Compose merges that file automatically.
```yaml
services:
  postgres:
    ports:
      - "127.0.0.1:${POSTGRES_PORT:-5432}:5432"
```
Then run `docker compose up -d postgres` and connect with:
- Host `127.0.0.1`, port `5432`
- User, password and database from your `.env`
- `sslmode=disable`

If you already run a local Postgres on 5432, set `POSTGRES_PORT=5433` in `.env` and use that port.

I'd go with option 2, kept local only: add `docker-compose.override.yml` to `.gitignore`. That way the default stack stays locked down and you get the port for development.
